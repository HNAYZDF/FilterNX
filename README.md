## 一、它是什么

本插件通过 **Fizeau** 这个系统模块给整个画面加滤镜。

分工很明确：

| | 负责什么 |
|---|---|
| **超能滤镜**（本插件） | 中文界面、100 种调好的滤镜预设 |
| **Fizeau**（系统模块） | 实际的色彩处理 |

所以**需要机器上装有 Fizeau**——4IFIR 等整合包通常自带。

### 核心特性

| 特性 | 说明 |
|---|---|
| **按下即生效** | 走 Fizeau 的 IPC 服务，不需要重启 |
| **100 种中文滤镜** | 分十一类：基础 / 护眼 / 风格 / 电影 / 氛围 / 游戏 / 怀旧 / 夜间 / 调光 / 单色 / 色觉辅助 |
| **状态实时刷新** | 「当前画面」会回读 Fizeau 的真实状态 |
| **全中文界面** | 字形取自主机系统共享字体，无内置字体文件 |
| **不影响性能** | 处理发生在显示管线，不占用游戏渲染资源 |
| **不碰硬件** | 不驱动硬件、不装 sysmodule、不申请内核能力 |

## 二、安装

把 `switch` 文件夹合并到 SD 卡根目录：

```
SD:/
└── switch/.overlays/
    └── Chaoneng.ovl      ← 唯一的功能文件（文件名必须是纯 ASCII）
```

**不需要安装 sysmodule，不需要配置文件。**

> ⚠ 早期用过 `FilterNX.ovl` 这个名字，改名后请删掉旧文件，
> 否则列表里会出现两个条目。

### 关于显示名与文件名（重要）

⚠ **文件名必须是纯 ASCII。** 试过命名成「超能滤镜.ovl」，
结果大气层**完全无法识别**这个 overlay——根本没出现在列表里。

正确做法是把两者分开：

| | 值 | 说明 |
|---|---|---|
| 文件名 | `Chaoneng.ovl` | 纯 ASCII，决定文件能否被加载 |
| 菜单显示名 | `超能滤镜` | 写在 **NACP** 里 |
| 菜单显示版本 | `5.0.0` | 写在 **NACP** 里（与 `version.hpp` 同源） |

菜单读取逻辑（Ultrahand-Overlay `source/utils.hpp:953` `getOverlayInfo()`）：

```cpp
fread(&nacp, sizeof(NacpStruct), 1, file);
memchr(nacp.lang_data.lang[0].name, '\0', ...)   → 显示名
memchr(nacp.display_version, '\0', ...)          → 显示版本
```

之后 `source/main.cpp:6894` 还会用 `config/ultrahand/overlays.ini` 里的
`custom_name` / `custom_version` 覆盖（非空时）。

### NACP 字段偏移（踩过的坑）

```
NacpLanguageEntry 步长 = 0x300  (name 0x200 + author 0x100)   ← 不是 0x200
isbn            @ 0x3000    ← 曾把版本号误写到这里，菜单读不到
display_version @ 0x3060    ← 真正的版本字段
```

偏移由 `tests/verify_nacp_offsets.c` 依据 libnx 官方 `nacp.h` 让编译器实测，
定义统一在 `tools/nacp_layout.py`。

## 三、Fizeau 没运行怎么办

**Fizeau 的系统模块必须重启才生效**——它要在开机阶段接管
nvnflinger 的显示管线（配合 `atmosphere/exefs_patches/nvnflinger_cmu/`
下的 27 个补丁）。所以运行时没法"启动"它。

**Fizeau 没运行时，插件不会崩也不会卡死**，只显示一个纯提示页：

```
【未检测到 Fizeau】
【怎么启用】
  第一步    特斯拉菜单
  第二步    系统模块
  第三步    启用色彩调节
  第四步    重启机器
【说明】
  为何要重启  开机接管
  本插件      不碰硬件
```

> 这一页**没有任何按钮、没有任何 IPC** —— 刻意做成纯展示。
>
> 曾经有过一个「连接色彩调节」按钮，按下会调用 `pgl` 启动系统模块。
> 真机结果：**点下去卡死**。原因是 `pgl` 是给 qlaunch（系统外壳）用的服务，
> 从 applet 里调用它**不会返回错误码，而是直接挂住** —— 比崩溃更糟。
>
> 教训：「调用失败会返回错误码」这个假设**不成立**。
> 对权限不明的服务，正确做法是**根本不调用**。

### 正确的启用步骤

1. 打开特斯拉菜单（`L + 十字键下 + 右摇杆按下`）
2. 进入 **系统模块**（`ovl-sysmodules`）
3. 找到 **色彩调节**，把它启用
4. **重启机器**（关键，不重启不生效）
5. 重启后打开超能滤镜，就能正常用了

### 也可以直接放标志文件

Fizeau 的开机自启动开关是：

```
atmosphere/contents/0100000000000F12/flags/boot2.flag
```

放一个 0 字节的空文件到那里（`flags` 目录不存在就新建），
然后重启，Fizeau 就会自动运行。

> ⚠ 如果卡上用过"换包工具"，它可能用备份整体覆盖 SD 卡，
> 把这个文件冲掉。被冲掉后按上面的步骤重新做一次即可。

## 四、100 种滤镜

每个预设都经过这些检验（由 `tests/test_presets.cpp` 断言）：

1. **至少有一个参数偏离中性值** —— 否则按下去毫无变化
2. **任意两个预设的完整参数集都不同** —— 否则用户看不出区别
3. **名字互不重复、且没有名字是另一个的前缀** —— 避免列表里看错
4. **数值全部落在 Fizeau 合法范围内** —— 越界会被静默钳制
5. **分级预设的相邻档位差距足够** —— 否则号称"四档"实际看不出区别

### 基础

| 预设 | 说明 |
|---|---|
| 原色 | 不处理。参数与 Fizeau 的 `DEFAULT_*` 完全一致 |

### 护眼（六档，色温逐级降低）

色温越低蓝光成分越少。相邻档色温差 ≥600K（6200→5600→5000→4200→3400→2800），
两端差距足够肉眼可辨。

| 预设 | 色温 | 饱和度 | 伽马 |
|---|---|---|---|
| 极轻护眼 | 6200K | 0.97 | 2.35 |
| 办公护眼 | 5600K | 0.93 | 2.28 |
| 轻度护眼 | 5000K | 0.95 | 2.30 |
| 中度护眼 | 4200K | 0.88 | 2.20 |
| 深度护眼 | 3400K | 0.80 | 2.15 |
| 纸质 | 2800K | 0.70 | 2.10 |

### 风格

| 预设 | 取向 | 关键参数 |
|---|---|---|
| 鲜艳 | 浓艳 | 饱和 1.50、对比 1.15 |
| 动画 | 高饱和 | 6800K、饱和 1.55、提暗部 |
| 冷色 | 偏蓝 | 8200K、色相 -0.04 |
| 暖橙 | 偏橙 | 5400K、色相 +0.03 |
| 高反差 | 强对比 | 对比 1.45、伽马 2.10 |
| 柔和 | 降反差 | 对比 0.85、伽马 2.50 |
| 复古（怀旧类） | 泛黄 | 4600K、饱和 0.65、伽马 1.95 |
| 褪色 | 旧照片 | 饱和 0.55、范围 6%~94% |

### 电影

| 预设 | 取向 | 关键参数 |
|---|---|---|
| 冷调电影 | 青蓝 | 8200K、色相 -0.05、对比 1.25 |
| 暖调电影 | 橙调 | 5400K、色相 +0.04、对比 1.20 |
| 青橙调 | 红青分离 | 7000K、饱和 1.20、色相 -0.06 |
| 黑色电影 | 低饱和 | 饱和 0.40、对比 1.35、伽马 2.60 |

### 调光（压 range，不降 luminance）

通过**压缩色彩范围**压低亮度，而不是降低 luminance——
压 range 是把输出区间挤到低位，**暗部层次保留得更好，不易死黑**。
两者也不叠加（由测试断言强制）。

| 预设 | 亮度 |
|---|---|
| 轻度调光 | 65% |
| 中度调光 | 35% |
| 深度调光 | 18% |
| 调光暖色 | 28% + 5000K |
| 调光冷色 | 30% + 7600K |

### 单色

> Fizeau 的 `filter` 不是"只留某个通道"。它把**亮度**按
> `0.2126 / 0.7152 / 0.0722` 的权重写进所选通道，其余通道输出 0。
> 所以画面是"灰阶染色"，且**亮度被正确保留**。

| 预设 | 效果 |
|---|---|
| 黑白 | 饱和度 0，完全去色 |
| 硬黑白 | 去色 + 对比 1.55 + 范围 3%~97% |
| 单色绿 | 绿通道承载亮度 |
| 单色暖黄 | 绿通道 + 4000K，琥珀终端观感 |

### 色觉辅助

> ⚠ 这**不是医学意义的色盲矫正**，而是**色相旋转 + 提高饱和度/对比度**，
> 把容易混淆的颜色拉开差距。效果因人而异。

| 预设 | 做法 |
|---|---|
| 红绿辅助 | 色相 +0.18、饱和 1.35 |
| 蓝黄辅助 | 色相 -0.20、饱和 1.30 |
| 高辨识 | 饱和 1.70、色相 +0.10、对比 1.40 |
| 视觉舒缓 | 5200K、饱和 0.75、降刺激 |

## 五、字体与排版

界面文案的长度限制来自 libultrahand 源码的布局算法：

```cpp
m_maxWidth  = getWidth() - valueWidth - 66;     // 名字可用宽度
m_truncated = textWidth > m_maxWidth + 20;      // 超限即启用滚动
```

**一旦超限，名字会走滚动动画路径——静止时看起来就是被截断的。**

字体是 **stb_truetype** 渲染的系统共享字体（`plGetSharedFontByType`），
全角字符宽度 ≈ 字号：

| 元素 | 字号 | 上限 |
|---|---|---|
| 列表项名字 | 23 | 4 字（92px） |
| 列表项数值 | 20 | 5 字（100px） |
| 当前效果摘要 | — | 10 字 |

### 还有一条硬约束：可见高度

```cpp
// List::draw() 的裁剪矩形
enableScissoring(0, 88, FramebufferWidth, FramebufferHeight - 73 - 97 + 2 + 5);
// 720 下可见高度 = 557
```

裁剪是**硬性**的，超出部分不会被画出来，必须滚动才能看到；
而恰好跨在底边上的那一行会被从中间切开。

各页实测（行数按 `gui.cpp` 的 `addItem` 调用点数出）:

| 页面 | 行数 | 高度 | 结果 |
|---|---|---|---|
| 未连接引导页 | 3 小标题 + 6 项 | 33 + 3×33 + 6×70 = 552 | ≤ 557，整页可见 |
| 主页面（已连接） | 3 小标题 + 6 项 | 33 + 3×33 + 6×70 = 552 | ≤ 557，整页可见 |
| 信息页 | 3 小标题 + 7 项 | 33 + 3×33 + 7×70 = 622 | > 557，需滚动 |

主页面的硬要求有两条（`tests/test_layout.cpp` 断言，
`tools/check_preview_clip.py` 从裁剪矩形那一侧复核同一条要求）:

1. **整页放得下** —— 它是"一屏看全"的页面，掉到裁剪区外的行用户发现不了。
   ⚠ 3 个小标题下最多 6 项；再加一项就是 622 > 557，底行被切。
   （曾经是 8 项 = 692px，「关于本插件」这个入口就被切掉了。）
2. **首屏含全部关键入口** —— 状态行 + 操作项 = `33 + 2×33 + 5×70 = 482 ≤ 557` ✓

这些常量集中在 `overlay/src/layout.hpp`，**真机与测试引用同一份定义**。

## 六、OLED 用户请注意

**OLED 屏幕在低亮度下用 PWM 调光，会产生频闪**。
OLED 通常采用 PWM + DC 混合调光：**亮度较高时走 DC，低亮度才切 PWM**。

推荐这样用：

1. **先把系统亮度调到最亮**（让面板工作在 DC 区）
2. **再用「调光」类预设降低感知亮度**

> 顺带说明：**真正意义上的"DC 调光"在 OLED 上不成立**——
> OLED 没有背光层，每个像素自己发光。所以任何工具做的都不是
> "变成 DC"，而是改变 PWM 特性。

**LCD 用户**没有频闪问题，直接选预设即可。

## 七、能做什么、不能做什么

| ✅ 能做 | |
|---|---|
| 色彩调节 | 色温、饱和度、色相、对比度、伽马、亮度、色彩范围 |
| 单色滤镜 | 黑白 / 硬黑白 / 绿 / 暖黄 |
| 一键预设 | 100 种调好数值的中文滤镜 |
| 画面调光 | 通过压缩色彩范围压低亮度 |
| 实时生效 | 按下立即看到变化 |

| ❌ 不能做 | 原因 |
|---|---|
| ReShade 式后期 | 锐化/色差/LUT 需注入游戏渲染管线 |
| 硬件级 DC 调光 | 见上文，OLED 上概念本身不成立 |
| 调节背光亮度 | 需要内核权限，标准大气层不开放 |
| 逐游戏不同配置 | Fizeau 只区分掌机/底座两档 |
| 运行时启动 Fizeau | 它必须重启才生效（开机接管显示管线） |

## 八、技术实现说明

### 为什么用 Fizeau 而不是自己驱动硬件

早期版本尝试自带 sysmodule 直接驱动 Tegra CMU，需要同时满足四个条件：
PFS0 打包正确、内核能力被接受、框架版本匹配、IPC 协议一致。
**任一条不满足就完全不可用**，而且大多不产生任何日志。

改用 Fizeau 之后：
- 不需要申请内核能力 → 没有拒载风险
- 不需要开机加载 sysmodule → 没有启动时序风险
- 走它已验证的驱动层 → 没有硬件访问风险

### IPC 协议

Fizeau 注册了 `fizeau` 服务：

| 命令 | 编号 | 输入 → 输出 |
|---|---|---|
| GetIsActive | 0 | 空 → u8 |
| SetIsActive | 1 | u8 |
| GetProfile | 2 | u32 → FizeauProfile |
| SetProfile | 3 | {u32, FizeauProfile} |
| GetActiveProfileId | 4 | u8 → u32 |
| SetActiveProfileId | 5 | {u8, u32} |

结构体布局（**已由 `tests/test_fizeau_proto.cpp` 逐字段验证**）：

```
FzSettings  32 字节: temperature(0) saturation(4) hue(8) contrast(12)
                     gamma(16) luminance(20) range(24)
FzProfile   92 字节: day_settings(0) night_settings(32) components(64)
                     filter(68) dusk/dawn(72..88) dimming_timeout(88)
```

### 「没开后台也不崩」是怎么保证的

这是本插件最严重的一次故障：**Fizeau 未运行时打开插件，整个特斯拉菜单会消失。**

反复排查都没根治，而且每次验证都要重新装卡、重启、复现，代价太高。
所以现在不再靠猜，改用**两步走的工程手段**：

**一、把连接挪到最安全的位置**

| 位置 | 做法 | 理由 |
|---|---|---|
| `initServices()` | **只写日志，零 IPC** | 这是 overlay 生命周期最脆弱的位置 —— 加载器刚完成解包与重定位就调用它，此刻任何失败都可能带走整个菜单进程 |
| `MainGui::createUI()` | **先建界面 → 再连接** | 万一"连接"这个动作本身会让进程死掉，界面已经在屏幕上了，最坏只是显示"未连接" |
| `refresh_state()` | **只读，绝不建连接** | 它被 `update()` 周期调用，若会连就等于每帧重连 |
| `connect_fizeau()` | 唯一的连接入口 | 职责单一，便于日志定位 |
| 每个 IPC 函数 | `session_ready()` 守卫 | 拿不到会话就返回错误，绝不拿空句柄发请求 |

**二、加逐步日志 —— 这是本次最重要的改动**

每一步都写进 SD 卡。路径**必须全 ASCII**——中文目录名会让 mkdir/fopen
直接失败，日志文件根本不会出现（第一版就是这么白加的）：

```
sdmc:/config/filternx/log.txt        ← 常规位置
sdmc:/filternx_log.txt               ← 卡根目录的退路（前一个写不了时用）
```

一旦崩溃，**日志的最后一行就是崩溃前最后执行到的地方**，不用再猜。

日志示例（Fizeau 没在运行的那条路径，**零 Fizeau IPC**）：

```
──────── 超能滤镜启动 ────────
[main] initServices 进入（本阶段不做任何 IPC）
[main] loadInitialGui 进入
[main] loadInitialGui 完成
[gui] createUI 进入
[gui] sm 会话有效
[gui] 探测: fizeau 服务未运行
[gui]   并且卡上没找到 Fizeau（未安装）
[gui] 服务未运行 → 显示提示页（零 IPC）
[gui] 显示提示页（本次未连接）
```

Fizeau 在运行时会多出这几行（`connect` 前缀的行就是"真正发 IPC"的那一步）：

```
[gui] 探测: fizeau 服务在运行
[gui]   connect: 调用 fzInitialize()
[gui]   connect: 会话已建立
[gui] 已连接，显示正常界面
[gui] 已连接，构建正常界面
```

如果日志停在 `[gui]   connect: 调用 fzInitialize()` 而下一行没有出现，
那就**确凿地**说明问题出在连接这一步 —— 这比任何猜测都有价值。

由 `tools/check_fizeau_safety.py` 与 `tools/check_connect_reachable.py`
从两个方向核对上述不变量（既保证"能连上"，也保证"连不上不崩"）。

## 九、从源码构建

```bash
cd overlay
export DEVKITPRO=/opt/devkitpro
make
# 产物: FilterNX.ovl（打包时改名为 Chaoneng.ovl）
```

依赖：`devkitA64` + `libnx 4.12.0` + `switch-curl/zlib/minizip/mbedtls`，
libultrahand 已收编在 `../third_party/libultrahand`。

```bash
powershell -File verify_all.ps1
```

25 项检查，**主机侧共 159 项断言 + 42 项全链路审计**：

| 检查 | 内容 |
